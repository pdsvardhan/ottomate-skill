# Phase 1 — PLAN (Ottomate design-system rebuild) · authored 2026-07-29

**The live, legible, decompose-and-ask loop — the fix for the exact failure the cointrail test hit.**
From spec §5 Phase 1 + the owner's clarified vision (test-run F-13…F-17). Governed by §7: each WS ends with
**evidence** (run it, must-fail where a gate is involved, render light+dark where visual). Phase 0 built the
substrate (`docs/plans/2026-07-29-phase-0-completion.md`); this makes a design **viewable, live, legible**.

**Payoff at the end:** re-run the cointrail `cointrail.spending-analysis` redesign *for real* — it will be
reachable, fully interactive, and the owner will know exactly what each round decides.

**Sequence (dependency order):** WS1.0 wiring → WS1.1 live preview → WS1.2 legibility banner → WS1.3
decompose-and-ask + always-ask → WS1.4 the real cointrail re-run.

## WS1.0 — Wire Phase 0's gates into the enforced pipeline (close the named gap)
Phase 0 built the contrast gate + lint as proven standalone tools; this makes them the *actual* gate.
- Call `contrastGate(theme)` as a **fail-closed publish gate** in the pre-publish path (design-round /
  publish-round / `computed-runner` blockingFindings), keyed on the project's theme file.
- **Retire `colourBudget`** as a blocking check (F-8): downgrade it to advisory or remove it, since the
  per-theme contrast gate + the "not colour alone" floor now cover legibility correctly. Update
  `design-rules.json` (`colour_budget.status`) + its `enforced_by`.
- Run `ban-raw-values` over each Block/Part source pre-publish; **hard findings block**.
- **Acceptance:** a round whose theme has an invisible pairing is **blocked** with the pairing named; a
  legitimate >4-category cointrail data-viz **publishes** (F-8 unblocked); a Block with a raw hex is blocked.
- **Verify:** run the publish path on (a) a good round → passes, (b) the broken theme → blocked, (c) a
  raw-hex Block → blocked. Show all three + the retired-colourBudget diff. Unit tests for the wiring.

## WS1.1 — Live preview engine (Ladle iframe-grid) — fixes F-14 + F-10
Replace the JS-inert static DSD panel with a **real** render of each variant.
- Stand up a per-project **Ladle** isolation server (Vite-native) that renders each variant as an
  auto-generated fixture importing the **real component** (start with cointrail; a `design-mode` Next.js
  route is the fallback if Ladle-in-repo is heavy). Expose it via the tunnel→authentik→container path
  (WS0.1 routing) so the owner opens a **reachable** URL.
- Ottomate's design surface shows a **grid of iframes**, one per variant, **full-size** (fixes F-10's
  squeezed compare view — each wide variant gets its own frame), with real hover / motion / 3D / charts.
- A postMessage bus for "interact all" / viewport sync (stretch; single-frame interactivity first).
- **Acceptance:** for a ≥2-variant round, the owner opens one reachable URL and sees each variant render
  **live** (a hover/animation/3D effect actually runs) at **full width**, side by side.
- **Verify:** drive it in real Chromium — capture a variant mid-interaction (hover state changed, a number
  counted up); render the grid light + dark; show the reachable URL returns 200 from a client.

## WS1.2 — Legibility banner — fixes F-17 (the owner's sharpest complaint)
Every round leads, in plain language, with **what it decides and what is held**.
- The round packet computes and the surface renders, LOUD and first (never a buried subtitle):
  **"This round decides: [X, Y]. The N versions differ ONLY in that; everything else is held. Pick one or
  mix."** — enumerated from the round's actual contested axes + the frozen controls.
- **No silent deferrals:** if an axis (e.g. motion) is pushed to a later round, the banner says so and the
  flow gets explicit assent — never a silent "round 2."
- **Acceptance:** a published round's page states, in a prominent banner, the exact axis/axes it decides and
  names what is held constant; a deferral is stated and assented to, not silent.
- **Verify:** render a round; show the banner text is generated from the round's real axes (not hand-typed);
  a must-show negative — a round that tries to defer an axis without assent is flagged.

## WS1.3 — Decompose-and-ask for one Block + always-ask scope — fixes F-15 (+ F-4, F-9)
On "redesign X," **decompose first, then ASK** — never silently choose scope.
- On a redesign request, inspect the real component and present its **anatomy** (Section → changeable
  dimensions: layout, type, data-presentation, Behaviors), driven by the anatomy graph + `data-role`/
  `data-oid` stamping (Phase 0's Block is already stamped), **not name-guessing** (F-4).
- **Always ask** (owner ruling): *which* sub-structure (whole Block / one Section / one property) and *how
  deep*, via an explicit `AskUserQuestion` — anything from a font to a border animation. Then variants
  explore **that** — one-property cycles OR whole directions by the owner's explicit choice (F-9).
- **Acceptance:** given a real Block, the tool lists its decomposable parts and **asks** what to change +
  at what granularity before generating; the chosen scope drives what varies vs what's held (feeds WS1.2).
- **Verify:** run the decomposition on the cointrail category-breakdown Block; show the parts list came from
  the anatomy/`data-role` (not a name heuristic) and the scope question was asked, not assumed.

## WS1.4 — The real cointrail re-run (the proof Phase 1 worked)
- With WS1.0–1.3 in place, re-run the `cointrail.spending-analysis` redesign end-to-end: decompose-and-ask →
  taste-grounded, expressive variants → live full-size preview → legibility banner → pick/mix/lock.
- **Acceptance:** the owner can *see and run* the round, *understands* what it decides, and the variants
  reflect the taste (3D/animated/glow proposed, not flat) — the five things the first run failed on.
- **Verify:** owner walkthrough; screenshots of the live grid + banner; the round publishes through the new
  gates (WS1.0). *This is where the parked r1 round is superseded — offer the rollback + findings audit here.*

## Risks / dependencies
- **Ladle-in-repo cost** per project — if heavy, the `design-mode` Next.js route is the pragmatic fallback
  for cointrail (it already has the components + a reachable host).
- **Authentik SSO on the preview URL** — the owner is authenticated; an unauthenticated share needs a
  bypass rule or a signed preview (note, not block).
- **Decompose quality** still leans on model judgment where `data-role` is absent — cointrail's Phase-0
  Block is stamped; older components may need stamping first (F-4 standing note).

## Exit (apply §7)
Verify WS1.0–1.4 with evidence · record a Phase 1 completion note · plan Phase 2 (the intelligence:
onboarding intake + pattern/chart/motion dictionaries) with acceptance criteria.
