## A correction I have to make to my own P1 claim

P1's register entry says the new detectors were run against "11 real panels, all clean". **Six of
those eleven were not panels.** The r2 variant-set JSON stores `panelTemplate` as a *filename*
(`"panel-A-tight-below.html"`), and my harness fed that string to the detectors as though it were
markup. Every r2 verdict in that run was vacuous — it was checking a 24-character filename.

The r2 panels are not committed; `gen.mjs` writes them. Running it produces the six real files, and
against those, **every one fails `floor-reduced-motion`**. So the honest version of the P1 claim is:
5 real panels checked, 6 vacuous. That is corrected in the register as part of this unit, because a
"ran it on real markup" claim that silently checked filenames is exactly the failure mode this
program exists to catch — and I made it.

## The work

1. **`floor-reduced-motion` — fix the generator, not the output.** Add a `prefers-reduced-motion:
   reduce` block to `gen.mjs`'s panel CSS, regenerate the six r2 panels, and hand-fix the three
   committed r1 panels. Re-run the detector on all nine and show it clean.
2. **`adv-no-slop-tells`** — remove the 3px coloured left strip from `template.card-wall.html` and
   the emoji from **both** templates, replacing the emoji with inline SVG per `adv-icon-delivery`.
3. **State captions** — raise `--dim2` until it clears 4.5:1, computed rather than eyeballed.
4. **`actionLabels` reads the accessible name.** `aria-label` wins over inner text when present.
   Must-fail and must-pass, plus a regression case using a real panel's icon button.

## Explicitly NOT doing: republishing the live rounds

The queue says "and republish". **I am not republishing**, and this is the reason:

The owner is mid-decision on Screenroom r1/r2 — decisions 18–27, all `in-review`, and the one thing
the program is blocked on. `publish-round.mjs` writes rows into `design_decisions`. Re-running it
against rounds the owner is actively judging risks duplicating or disturbing those rows, and the
benefit does not justify it: a `prefers-reduced-motion` block changes **nothing** about what the owner
is choosing between — it is inert unless the viewer has asked for reduced motion.

So the fix lands in the source of truth (`gen.mjs` and the committed panels), the panels are proven
clean, and **republishing waits for the owner's word**. Recorded here so it reads as a decision, not
an omission.
