# Ottomate — web project pipeline skill

One system, two halves: this skill plugin (the judgment and dialogs) and the Ottomate web app on VAULT7A (the state, gates, and evidence). They version together; review changes to one against the other.

## Invoke

```
/ottomate                          List projects, pick one
/ottomate <project-slug>           Resume a project
/ottomate new                      New-project flow (Stage 0)
/ottomate <slug> <text>            Stage 4 intake with raw text
```

Pipeline: Stage 0 preprocess → 1 spec (SO1) → 2 UI/tech → 3 build/test/deploy → 4 iterate. Stage transitions are gated; gates only reference state the API can write (adr-014).

## Where truth lives

This README holds **no counts and no status claims** — they drift. Instead:

- **Live state** → `STATUS.md`, generated by `bash scripts/generate-status.sh > STATUS.md` (adr-016). Or query the app directly.
- **Decisions** → ADR index in the app (`/api/projects/<slug>/adr-index`); bodies in `decisions/` of the tracker repo. Plugin-relevant: adr-012…016 (2026-06-10 batch).
- **History** → `_archive/` (REQUIREMENTS, PILOT_ONBOARDING, pre-v3 planning docs — historical record, not live spec).
- **The 2026-06 audit** (full critique, findings, workstream plan) → `~/Desktop/Skills CC/Ottomate/AUDIT-2026-06-10.md`.

## Companion web app

`/opt/homeserver/ottomate` on VAULT7A — Next.js + drizzle + SQLite, container `ottomate`, bound `127.0.0.1:8110` server-side; public route `ottomate.vault7a.xyz` via Authentik (read-gating lands in WS3; risk instance 59 tracks the interim acceptance). Mutations require the bearer token at `/opt/homeserver/ottomate/.token`.

```bash
ssh -L 8110:127.0.0.1:8110 pdsv@192.168.1.10   # then http://localhost:8110
```

SSH is key-only (password auth disabled 2026-06-10). No credential values live anywhere in this plugin — see `skills/ottomate/references/credentials.md` for the locations-only map.
